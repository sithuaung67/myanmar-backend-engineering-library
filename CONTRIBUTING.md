
# 🤝 Contributing Guide

Thank you for your interest in contributing to the Myanmar Backend Engineering Library.

This project aims to build a high-quality backend engineering reference library for the Myanmar developer community.

We welcome contributions of all sizes, including documentation improvements, bug fixes, code examples, diagrams, and new learning materials.

---

# 📌 Before You Contribute

Please make sure you have:

- Read the README
- Checked existing Issues
- Followed our Style Guide
- Tested all code examples
- Used clear commit messages

---

# 📚 Types of Contributions

You can contribute by:

- Improving documentation
- Fixing typos
- Adding better explanations
- Improving diagrams
- Adding production best practices
- Updating outdated examples
- Reporting bugs
- Suggesting new topics

---

# 📝 Writing Guidelines

Please follow these principles.

## 1. Accuracy First

Only write information that has been verified.

---

## 2. Explain Why

Don't only explain *how*.

Always explain *why*.

---

## 3. Production Mindset

Prefer production-ready examples over demo code.

---

## 4. Keep It Simple

Write for learners.

Avoid unnecessary complexity.

---

# 💻 Code Style

- PHP 8.3
- Laravel 12
- PSR-12
- Laravel Pint

Every code example should be runnable whenever possible.

---

# 📖 Documentation Style

Every chapter should include:

- Learning Objectives
- Explanation
- Example
- Best Practice
- Common Mistakes
- Interview Questions
- Summary

---

# 🔍 Pull Request Checklist

Before submitting a Pull Request:

- [ ] Documentation reviewed
- [ ] Grammar checked
- [ ] Code tested
- [ ] Formatting verified
- [ ] No duplicate content
