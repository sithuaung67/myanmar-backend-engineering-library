# 📝 Documentation Style Guide

This document defines the writing, formatting, and engineering standards used throughout the Myanmar Backend Engineering Library.

Following a consistent style helps maintain quality, readability, and long-term maintainability.

---

# 🎯 Our Principles

We follow five core principles.

1. Accuracy First
2. Clarity Over Complexity
3. Explain Why Before How
4. Production Mindset
5. Consistency Matters

---

# 📚 Writing Style

Write in simple, professional language.

Avoid unnecessary jargon.

Explain difficult concepts step by step.

Always prefer practical examples.

---

# 📖 Chapter Structure

Every chapter should follow this structure.

1. Title
2. Learning Objectives
3. Introduction
4. Core Concepts
5. Practical Examples
6. Best Practices
7. Common Mistakes
8. Interview Questions
9. Hands-on Exercise
10. Summary

---

# 💻 Code Style

Target Platform

- PHP 8.3
- Laravel 12

Follow:

- PSR-12
- Laravel Pint

Code should be production-ready whenever possible.

Avoid unnecessary shortcuts.

---

# 📦 Naming Convention

Use meaningful names.

Good

CustomerController

OrderService

PaymentGateway

Bad

TestController

Demo

ABC

Temp

---

# 📄 Markdown Style

Use

# for Chapter

## for Section

### for Subsection

Always leave one blank line between sections.

Avoid long paragraphs.

---

# 💡 Notes

Use consistent callouts.

⚠️ Common Mistake

✅ Best Practice

🧪 Hands-on Exercise
